# 已知限制

## 统计范围

- 不是原子快照：采集过程中日志和文件仍可能变化，数值之间可能存在时间差。
- 分区使用量包含文件系统自身数据、保留空间及其他机制；工具不承诺解释每一个字节。
- 目录使用 `st_blocks × 512`，与逻辑文件大小不同。共享块、压缩、快照和配额可能导致差异，不能把目录大小理解成删除后一定释放的大小。
- 不跨子挂载点，包含同设备的绑定挂载；扫描中新增或移动挂载点仍可能影响边界，繁忙主机需要人工复核。
- 深层目录、权限不足、对象变化及时间上限可能使结果不完整；目录前 20 项是已扫描部分的排行。
- 目录递归最多 128 层，超过的分支标为未读取；硬链接去重记录随文件数量增长，超大目录建议缩小检查范围。
- 系统日志只统计当前身份能看到的日志，不读取普通应用日志正文，不扫描所有日志文件。
- 系统日志命令只要附带标准错误提示，就保守标记“部分完成”。这包括“未找到日志文件”的提示：命令明确报告的 0B 会保留为已知零，但状态不会提升为全量完成；未知或权限不足不据此填零。
- Docker 默认只检查 `/var/run/docker.sock`。不自动识别无根 Docker、自定义连接路径、远程连接或 Docker Desktop。
- 辅助命令只在 `/usr/sbin`、`/usr/bin`、`/sbin`、`/bin` 中查找，不继承用户 PATH；仅安装在自定义目录的命令会显示工具缺失。
- 容器日志首版仅统计 `json-file` 当前文件和标准数字编号轮转文件的元数据。其他驱动明确标为未统计。
- Docker 服务查询权限与日志文件权限分别判断。加入 Docker 用户组不代表能够读取管理员所有的日志目录；根目录无法访问时，报告整体日志权限不足，不生成尚未读取的逐容器行。
- 已删除占用仅查 `/proc/PID/fd` 的普通文件，不覆盖仅由内存映射持有的文件、隐藏的进程空间及其他容器命名空间。普通用户的可见范围不能当作全机结果。
- 已删除文件统计首版仅认可 ext2、ext3、ext4、xfs；其他文件系统明确说明未扫描，不把内存文件系统的占用解释成硬盘空间。
- 元数据检查不是原子快照，极短时间内连续多次复用同一个文件描述符仍无法绝对排除；发现可观察的变化时标记不完整。

## 使用和安全

- 不提供清理操作或建议执行的破坏性命令；Docker 的“可回收”数值没有业务安全保证。
- 默认不保存数据。显式保存只写新的报告目录，保存失败时可能保留未完成文件，会明确报错。
- 报告输出路径不能经过符号链接。持有原目录后发生路径替换不会重定向写入替换目标，但可能在已改名的原目录留下未完成文件；程序不会自行删除这些文件。
- 命令行选定目录后持有其描述符。原路径被重命名或替换时，后续检查会停止或标为部分完成，已取得的数据属于原目录。目录内部仍可能并发变化，报告不属于原子快照。
- 命令行会拒绝非默认的子进程回收信号策略；不支持嵌入有自定义 SIGCHLD 处理器的宿主程序。源码中的采集函数不是稳定公共接口。
- 系统只读权限并不能保证绝无访问时间或审计记录变化。
- 极端情况下内核不可中断的磁盘读取可能无法立即退出；工具停止等待并标记超时，不承诺内核任务瞬间消失。
- Linux 外的平台只显示不支持，不扫描；未验证的系统、架构或 Docker 版本不能标为已支持。

## 构建范围

构建脚本仅打包指定文档以及代码、测试目录中的 Python 文件，拒绝源码符号链接。单个源文件上限 8 MiB、全部源码合计上限 32 MiB、源码子目录最多 32 层。超过限制明确构建失败，不生成可分发成功提示。读取期间源文件发生可检测的变化时也拒绝构建。
