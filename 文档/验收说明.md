# 验收说明

## 本机单元与接口测试

在源码根目录执行 `python3 -B -m unittest discover -s 测试 -v`。测试将临时资料放在本项目的 `测试环境/临时`，不会连接现有服务器或真实 Docker。

测试包括真实子进程超时、受控环境、终端字符转义、独立报告保存、发布包可运行与文件白名单；文件系统样本包含普通文件、稀疏文件、硬链接和特殊名称。特定系统调用的错误通过有限边界模拟，不将模拟结果当作 Linux 实测。

## Linux 实际行为

需要专用、可重建的 Ubuntu 24.04 或 Debian 12 虚拟机。不得挂载个人资料，不得复用业务 Docker，不得填满系统根分区。

实际测试需验证：

1. 普通用户和管理员运行，权限不足不能显示完整。
2. 在专用样本目录创建普通/稀疏/硬链接文件，核对实际块数与排行。
3. 创建绑定挂载，验证不穿过同设备的挂载边界。
4. 创建小型专用文件系统，分别耗尽空间和文件节点；检查工具仍能报告，测试后仅处理该测试文件系统。
5. 保持文件打开后删除路径，验证文件和持有进程被找到，并在释放句柄后不再出现。
6. 对专用 Docker 的镜像、卷、构建缓存、json-file 轮转及其他日志驱动进行对照检查，不读取正文。
7. 验证超时、取消、报告路径不可写和已有报告不被覆盖。
8. 解压源码包及运行单文件包，确认发布物和开发入口功能一致。

记录系统、架构、Python、Docker、systemd 实际版本，以及每项通过、失败或未验证。未执行或跳过不能计为通过。测试后停止虚拟机，保留复现所需资料，不将密钥和真实报告放进发布包。

## 0.1.1 已执行的范围

Ubuntu 24.04 ARM/Python 3.12.3、Debian 12 ARM/Python 3.11.2、Debian 12 ARM/Python 3.10.21、完整 Debian 12 x86_64 软件模拟/Python 3.11.2，分别通过 147 项自动测试，以及基础 9 组 66 条、拓展 10 组 67 条真实断言。软件模拟不能替代原生 x86_64 性能和长期运行验证。

`测试/隔离验收.py` 和 `测试/拓展隔离验收.py` 是显式启动的隔离验收器，不会随默认测试命令自动执行。两者要求专用虚拟机、管理员身份、专用主机标识和所有权正确的确认文件；请勿为了在业务服务器执行而绕过这些保护。需要先在专用环境建立合成 Docker 和文件系统样本，复制脚本本身不代表环境已准备好。

测试通过表示预期行为成立，包括权限不足、缺工具和保存失败能够如实报告；不要求这些情况显示“完成”。早期验收曾有两项状态预期不符合既定规则，以及验收器保存特殊文件名的编码错误，保留原记录并修正测试后完成复测，没有因此把未知大小改为零。

### 本版修复与失败记录

- 文件描述符额度耗尽时，创建采集管道失败会明确返回失败，不再产生未处理异常。
- 连续两次取消不会打断辅助进程清理。
- 命令行持有选定目录的描述符；路径被替换时停止相关检查或标为部分完成，不再扫描替换目标并声称完整。
- 每次目录扫描结束及时释放文件索引，解决同进程重复扫描时的内存持续增长。

新增回归在修复前真实失败，修复后通过。Debian 首次负载在 234.225 秒时因一项测试预期失败：轮转期间所有列举到的日志文件发生变化，程序正确返回部分完成并省略未知大小，脚本却要求每次必须取得日志元数据。生产代码没有因此修改。验收条件修正为：变化期间必须明确部分完成、不得把未知大小填零；本次受控轮转负载至少 95% 的完整调用取得元数据；停止轮转后与原生 stat 精确对照。随后重新执行完整 600 秒，260 次完整调用均取得元数据，停止轮转对照通过。原始失败证据保留，未计入最终通过的十分钟次数。

### 验证边界

十分钟持续负载不等于数天或数月的生产稳定性证明。真实生产数据、长期大规模运行、其他发行版和 Docker 版本、原生 x86_64 的 Docker/挂载/负载场景仍未验证。0.1.1 曾在完整 x86_64 软件模拟系统通过旧版验收，不能冒充本版全部场景重新通过。macOS 仅用于开发测试，不支持功能扫描。默认 GitHub Actions 只执行单元与接口测试，不能替代这些专用虚拟机实测。
